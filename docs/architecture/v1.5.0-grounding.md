# Fundamentación Técnica y Auditoría — Cazador YTM v1.5.0

Este documento registra las fuentes técnicas verificadas y las decisiones arquitectónicas que respaldan las mejoras de la versión **v1.5.0**.

---

## 1. API de Letras LRCLIB (`MetadataService.cs`)
- **Fuente oficial**: [LRCLIB API Documentation (`https://lrclib.net/docs.md`)](https://lrclib.net/docs.md)
- **Decisiones verificadas**:
  1. **Identificación del cliente (`User-Agent`)**: LRCLIB requiere incluir nombre de aplicación, versión y enlace al repositorio o contacto (`CazadorYTM/<AppVersion> (https://github.com/RHcomunications/CazadorYTM)`).
  2. **Precedencia de `q` vs. parámetros estructurados en `/api/search`**: La especificación indica que cuando se incluye `q`, este toma precedencia e ignora `track_name` y `artist_name`. Por ello, `BuildLrclibCandidateUrls` prioriza:
     - `GET /api/get?track_name=...&artist_name=...&duration=...` cuando se dispone de artista y duración válida (`1..3600` s, tolerancia ±2 s en LRCLIB).
     - `GET /api/search?track_name=...&artist_name=...` (sin `q`) como respaldo estructurado.
     - `GET /api/search?q=...` como respaldo amplio.
  3. **Prioridad de formato y control de cuota (`429 Too Many Requests`)**: Se prioriza `syncedLyrics` sobre `plainLyrics` en respuestas tanto de objeto único (`/api/get`) como de arreglo (`/api/search`), y se detiene la secuencia de intentos ante HTTP `429`.

## 2. Especificación del Formato LRC (`LyricLine.cs`)
- **Estándar**: Formato LRC estándar con marcas de tiempo `[mm:ss.xx]` / `[mm:ss.xxx]`, múltiples marcas por línea (`[00:41.20][01:32.60]Texto`) y etiqueta global `[offset:+/-ms]`.
- **Implementación verificada**:
  - Expansión de líneas con múltiples timestamps en eventos cronológicos independientes.
  - Preservación de encabezados de sección entre corchetes (`[Chorus]`, `[Verse]`) cuando no son etiquetas de metadatos LRC.
  - Aplicación global de `[offset:+/-ms]` (desplazamiento positivo adelanta la aparición de la letra) con acotado a `TimeSpan.Zero` para evitar tiempos negativos.

## 3. Accesibilidad Universal WCAG 2.2 AA en WPF (`PlayerView.xaml`, `LiveRegion.cs`)
- **Referencia**: Microsoft WPF UI Automation (`AutomationProperties.LiveSetting`, `AutomationEvents.LiveRegionChanged`) y compatibilidad con NVDA / Narrador de Windows.
- **Implementación verificada**:
  - En WPF, cambiar el `Text` enlazado de un `TextBlock` con `AutomationProperties.LiveSetting="Polite"` no garantiza que los lectores de pantalla reciban la notificación si no se dispara explícitamente `AutomationEvents.LiveRegionChanged`.
  - Se utiliza la propiedad adjunta `acc:LiveRegion.Announce` ([LiveRegion.cs](../../src/CazadorYTM.Gui/Accessibility/LiveRegion.cs)) tanto en los anunciadores dedicados (`TrackLiveAnnouncer`, `VolumeLiveAnnouncer`, `SleepTimerLiveAnnouncer`) como en los indicadores dinámicos de estado (`QueueStatusText` y `LyricsStatusText`).
  - `ListLyrics` mantiene `SelectedIndex` en `Mode=OneWay` y omite `ScrollIntoView` cuando `!ListLyrics.IsKeyboardFocusWithin` es falso, evitando robar el foco o interrumpir la navegación por teclado.

---

## 4. Control de Velocidad de Reproducción (`AudioPlayerService.cs`)
- **Referencia**: Documentación oficial de Microsoft para `System.Windows.Media.MediaPlayer.SpeedRatio`.
- **Consideraciones verificadas**:
  - Microsoft advierte que la reproducción de audio no está garantizada en valores extremos de `SpeedRatio` y que ciertos cambios de estado pueden requerir reaplicar la propiedad.
  - La interfaz acota los saltos entre `0.75x` y `2.0x` (en incrementos de `0.25x`), y `AudioPlayerService` reaplica `_speedRatio` automáticamente en el evento `MediaOpened`.
